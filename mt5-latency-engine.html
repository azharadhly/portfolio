(Note 03)Trading · MetaTrader 5

Inside MT5’s latency engine

In a fast market, a quote can be out of date within milliseconds. MetaTrader 5 is built as a network of servers whose main job is to keep the trip from click to fill short.

Latency and execution

01One login, many servers

When a trader logs in, the MT5 terminal doesn’t talk to the trade server directly. A broker’s MT5 platform is a group of servers with separate jobs:

  • Access servers. Spread around the world. They accept the terminal’s connection and pass requests on, and they shield the trade server from attacks.
  • Trade server. The core. It holds accounts and positions, checks margin and executes orders.
  • History server. Stores price history, so charts load without slowing down trading.
  • Backup server. Keeps a live copy of the trade server, ready to take over.
  • Gateway. Connects the platform to liquidity providers and other markets.

The terminal measures the ping to the access points it knows and connects through the fastest. That is the first trick: put the entry point close to the trader.

03The speed of light is the limit

Light in optical fiber covers about 200 km per millisecond. Sri Lanka to London is about 8,700 km in a straight line and longer by cable, so one round trip takes at least 87 ms before a single router gets involved. Software can’t beat that. It can only move closer.

04Execution modes

Latency matters most in the moment between clicking and filling. If the price changes in that moment, MT5 handles it according to the symbol’s execution mode:

  • Instant execution. The order fills at the price the trader saw, or not at all. If the price moved, the trader gets a requote and can accept the new price.
  • Market execution. The order fills at the current price, whatever it is. No requotes, but the fill can differ from the screen. That difference is slippage.
  • Request execution. The terminal asks for a price first, then trades on it.
  • Exchange execution. Orders go to an external exchange and fill there.

05How traders and brokers cut latency

  • Host next to the trade server. Traders who run expert advisors use a VPS in the same data center, which can bring the round trip down to a millisecond or two.
  • Co-locate the gateway. Brokers put the trade server and gateway in the same data center as their liquidity providers. London’s LD4, New York’s NY4 and Tokyo’s TY3 are the usual forex hubs.
  • Add access servers. An access point near each big client region shortens the first network leg.
  • Skip Wi-Fi and mobile data for anything time sensitive. They add jitter as well as delay.

06Words to know

Latency
The time a message takes to get somewhere. In trading, usually measured in milliseconds.
Ping
A round trip test: how long it takes to reach a server and hear back.
Access server
An MT5 entry point near the trader that forwards requests to the trade server.
Trade server
The core MT5 server that holds accounts and executes orders.
Gateway
The link between MT5 and outside liquidity or exchanges.
Slippage
The difference between the expected price and the fill price.
Requote
A new price offered when the requested one is no longer available.
VPS
A virtual server rented in a data center, often close to the broker.
